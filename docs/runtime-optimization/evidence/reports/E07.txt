## Test and prototype

Real Q3_K-AntirezLike GGUF payloads from SSD:up/down experts of layers6/32;384 experts, six picks per token, actual shapes5120x2304 and2304x5120. Two recorded512-token chunks from Wiki/code8K runs; source/router ID selection comes from the prior Q3 MMQ report. These are not full512/8K prompts. Input activations are deterministic synthetic uniform[-0.125,0.125], not recorded model activations. All four real projection tensors are read-only and loaded resident before timing.

Baseline:production ggml_cuda_mul_mat_q, current Q3 MMQ32 and broadcast quantize/scatter where applicable. Prototype:offline CPU partition by assignments per expert; cold assignments use the existing Q3 MMQ kernel/J32, hot assignments use gather to FP16, dequantize that expert's weights once for the projection, cuBLAS FP16-operands GEMM with FP32 compute/output, scatter into original token/pick slots. A single expert scratch is reused serially on one CUDA stream. Down uses six input channels, up broadcasts one; output pick order is preserved. The cold input packing differs from the production helper; all-cold exactness/performance controls measure its effect.

Thresholds0(all-cold),32,64,128. Only the threshold predicate changes within the prototype. Candidate cold quantization, hot gather, weight conversion, GEMM and scatter are included. **Counts, CPU planning and index uploads are excluded**:there is no online GPU classifier/dispatcher, model graph integration, fit accounting or safe runtime fallback implementation. A host readback/synchronization in a future dispatcher could erase any kernel gain. No expert VRAM borrowing is used.

Each candidate and baseline is explicitly captured and replayed with fixed owned buffers; this does not prove runtime graph-cache reuse or pipeline ownership. Warmup, three ABBA rounds; each measurement launches ten graphs and synchronizes at the end, using host wall time. Reported baseline/candidate times are medians of the per-round paired means. CPU graph preparation/model read is excluded. Timing is not taken under compute-sanitizer. No Nsight kernel-selection proof or per-stage critical-path attribution is claimed.

The initial unpaired run showed timing drift and misleading isolated gains. It is archived at the report root as diagnostic history. Final acceptance uses only paired/ logs and manifests. Individual cases still vary; the result is a screening decision, not a statistical model-wide estimate.

## Arithmetic and memory gates

- Four projection cases x four thresholds per device. All-cold output is bit-exact to production MMQ32; every cold output row remains bit-exact in mixed hot/cold runs. All outputs finite. Every captured candidate was replayed three times with exact repetition.
- Independent reference for the hottest expert in each case(305/368 rows):CPU dequantize_q3_K weights and F32 cuBLAS GEMM; separately rounded FP16 weights/inputs converted back to F32 with pedantic F32 GEMM. FP16 GEMM versus the rounded reference NMSE remains below1e-10 on both devices.
- On these synthetic activations, FP16 versus CPU-dequant/F32 NMSE is about7.1e-8, MMQ about1.4e-5. This is **not** a PPL/NLL or model-quality improvement claim. MMQ quantizes activations to Q8_1; FP16/GEMM changes activation/weight rounding and reduction order. Mixed output differs from MMQ as expected. Teacher-forced text/code delta-NLL<=+0.01 nat/token remains a separate review gate if a faster runtime candidate is found.
- Ada direct execution and Ampere compute-sanitizer memcheck/leak-check passed. Final paired fixture runs all16 cases plus four references on each device; Ampere instrumented run reports0 errors/0 bytes leaked. Initial and paired reruns are repetitions, not independent coverage.
- Explicit candidate scratch is51,365,892 bytes(up) /45,402,116 bytes(down), about49.0/43.3MiB, including cold quantized rows, one dequantized expert, gathered input/output and routing indices. Existing cuBLAS/context pool, validation output/reference allocations and resident model tensors are additional. This is not a measured full-model peak VRAM/fit budget. Maya's combined gate/up workspace and this projection-level scratch are different layouts.

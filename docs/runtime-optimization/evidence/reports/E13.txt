# Compact Q8 verification: два KV-буфера, 2026-11-02

Реализация закоммичена в `my_maya`: `7cf70f283`. `LLAMA_DSV41_VERIFY_DUAL_KV` теперь default ON; `=0` отключает, `=1` явно включает. Описанные ниже gates выполнены на `24205e3e7` плюс [source patch](artifacts/source.patch) с явным ON. Документация предыдущего этапа закоммичена как b0b2ad2.

## Изменение

Для компактной Q8 verification на 2–6 токенов ordered raw KV остаётся отдельным пулом для каждого запроса. Shared compressed KV передаётся один раз через явный graph source7. Существующий MMA kernel выбирает адрес строки по прежнему виртуальному индексу raw+compressed; encoded Q8->half, tile boundaries, reduction, counts, sinks и порядок индексов сохранены. Убраны полные compressed arange/repeat/GET_ROWS_Q8 и CONCAT в принятом режиме. Проверка counts использует суммарное число raw+compressed строк. CUDA graph signatures уже обходят все GGML_MAX_SRC; новая зависимость участвует в учёте.

Eligibility: NVIDIA Ampere/Ada, Q8 K=V, D512/GQA64, один запрос на stream, streams2..6, raw1..1024, compressed>=24576, существующий compact producer с counts/sinks и independent reduction. Graph construction отдельно проверяет backend support. Decode1, prefill512, F16, parallel и неподходящие режимы остаются на прежнем пути. Общая внутренняя CUDA FA launch signature получила null/zero аргументы для прежних kernels; новый public helper только прикрепляет explicit shared source.

## Operator и память

На Ada CUDA0 и Ampere CUDA5 прошли по22 формы: streams2..6, raw1/31/127/128/256/640/1024, compressed24576/32768/106752, offsets2/16-byte padding, отрицательные/завышенные/нулевые counts, невалидные индексы и NaN в скрытых хвостах. Все выходы побитово равны reference с физическим объединённым Q8 KV и прежним MMA. Проверены input/output canaries; по132 отрицательных capability checks на архитектуру. Memcheck quick по2 крайних формы на каждой архитектуре: ERROR SUMMARY0. Это не racecheck и не матрица всех backends.

Первая попытка fixture остановилась до kernel на allocation-order assert: output view был создан раньше parent buffer. Исправлен порядок создания только во внешнем probe; исходный лог сохранён. CUDA сборка прошла; rebuild показал существующие предупреждения CPU enum cases и vector-insert в ggml-cuda.cu, эти участки не менялись.

## Workspace: найденная проблема и исправление

В первоначальном full server A/B все ответы совпали и TG98K вырос примерно на32%, но destructor ON выдал CUDA2 compute1875.03MiB вместо startup1856.26MiB. Gate был помечен FAILED; исходные результаты сохранены. Полный cache выбирал дешёвый dual graph, а промежуточные формы со старым packed fallback могли требовать больше workspace. Точный запрос, поднявший high-water mark, отдельно не локализован.

Исправление консервативное: synthetic reserve context сохраняет packed fallback как верхнюю оценку даже при ON. Эта же ветка используется no_alloc/auto-fit. Kernel и арифметика не менялись; SHA256 libggml-cuda до/после workspace fix одинаков. Поэтому снижение выделенного startup workspace из первой попытки больше не заявляется как результат; более точный резерв промежуточных форм остаётся отдельной оптимизацией.

После исправления native OFF/ON/OFF повторён. Metadata fit0/1: одинаковая оценка254887MiB, status0, ctx100352 и GPU layers41 без изменений размещения. Реальные native compute buffers OFF/ON совпали. Завершённый первоначальный OFF служит контролем финальному повтору ON: baseline-поведение OFF не менялось, но libllama candidate пересобран с исправлением reserve. Это сравнение corrected candidate с prior OFF build, а не same-binary flag-only A/B. Обе версии patch и hashes сохранены.

## Статус

Во время gates прототип был opt-in/defaultOFF; после них пользователь запросил default ON. Это завершённый bounded operator/native/server gate; не общий quality/PPL gate и не свежий matched Maya benchmark. Расширение на обычный decode1, F16, prefill или другие GPU требует отдельных capability/correctness/speed gates. Исходные веса/GGUF не менялись. GPU освобождены.

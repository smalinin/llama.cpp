# Q3: prefill FFN-region CUDA graph prototype, 2026-10-31

User instruction:reject the serial FP16/GEMM experiment, retain its report, continue with prefill stable-region reuse. FP16/GEMM never entered production; its standalone executables were removed and archived source/results retained. Current runtime/defaults remain MMQ32 and cache64/TTL10s. This report tests a separate isolated graph-region prototype.

**Decision after native A/B:** do not integrate this FFN-only region prototype. PP changes are about+0.16% on512,-0.02% on Wiki8K,+0.03% on code8K; there is no meaningful measured prefill gain. The native speed gate did not pass despite exact numerical/lifecycle checks. Keep the patch and evidence, continue with independent Engram lookup ownership. No production flag was added.

## Restricted candidate

Private experimental env GGML_CUDA_DSV41_PREFILL_REGIONS=1, default OFF; source/patch remain isolated in /tmp. Select a full FFN region from RMS_NORM before ffn_norm through ffn_out, only for full512-row chunks, 5120-wide embedding geometry(tested FF width2304),384 routed experts/six picks, Q3/Q4 routed weights resident on the same CUDA backend. Tail508, split/host/staged FFN, unsupported geometry, non-VMM/pre-Ampere/Hopper+ devices, disabled CUDA graphs and existing concurrent-event regions keep the original whole-graph path. Other architectures/parallel modes are not validated by these tests.

The region uses the original CUDA graph warmup/compatibility/property checks and cache. A graph view has UID0, forcing full property comparison rather than UID fastpath. The region key additionally includes data addresses/buffer handles and original full-graph node use counts. This retains distinct allocation/input-copy variants and invalidates the fusion contract when external consumers change. Uses are read from the original graph's global consumer table. No shape, source metadata, op parameters or pointer checks were removed.

Prefix/suffix ranges run through the existing eager CUDA evaluator. Event recording stays at the original backend/scheduler boundary after all slices; input-copy preparation, allocator fences, KV ordering, capture locks, VMM ownership and teardown are unchanged. No new GPU workspace or FP16 expert cache is added. Existing bounded per-context CUDA cache64/TTL10s is shared with ordinary graphs; it is not a byte budget. Capturing subregions changes fusion opportunities, so numerical and native gates are required rather than assumed.

## Numerical and lifecycle gates

- Synthetic full-width Q3 FFN fixture on Ada/Ampere:56 assertions per device, changing inputs, four RMS/norm buffer-address variants/revisits, explicit global consumer-count change creating a distinct region entry, and T508 fallback. Captured/replayed outputs are bit-exact to the whole-graph reference. Final Ampere memcheck/leak-check0 errors/0 leaks.
- Fixture v1 incorrectly required cache size to increase across a consumer-change check. Under slow memcheck, TTL can evict older entries. It failed that assertion; early error exit also omitted backend cleanup and sanitizer reported18MiB of VMM allocations. Saved under unit-v1. Final fixture checks new-key identity, not entry-count growth, and uses RAII backend cleanup. Runtime candidate was not changed to hide the fixture failure. No invalid CUDA read/write was reported in that first run.
- Full Q3 probe, separate OFF/ON contexts with one loaded target:six text/code prefixes512/8192 plus511/8191 tails, widths2..6,600 scored logits/NLL positions and30 partial rollback/resume trials. Prefix/end/restored KV, taps37..39 and resumed logits match exactly; delta-NLL0.
- That probe loads target with DSpark tap support, not the draft model itself. Actual BF16 draft is exercised by the native server test below.
- Actual quality trace:1715 region submissions,126 captures,667 pure replays; every region view UID0. This proves the branch runs, not that it is faster.

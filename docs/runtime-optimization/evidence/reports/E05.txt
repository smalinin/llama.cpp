## Что изменено

`LLAMA_DSPARK_GPU_FEATURES=1 LLAMA_DSPARK_GPU_FEATURES_LOCAL=1` задаются до запуска server, ASYNC=0 в этом опыте. Требования прежние: DS41,3 последних trained taps, single sequence, causal/offloadKQV, CUDA layer split, B<=8192/U<=512. Номера GPU не служат routing table.

Owners raw planes определяются из фактических tap tensors после scheduler split/probe. F32[hidden,B] и row scratch каждого tap остаются на probe producer. Packet device берётся из encoder FC при pair binding; отдельный standalone target API без consumer использует output GPU. После завершения target forward только нужный chunk копируется в collector, затем прежний F32 permute/CPY собирает packet. В target prefill нет новой зависимости от раннего encoder GPU; этот вариант отличается от отклонённого переноса всего retention наCUDA0.

Для текущего frozen layout: taps37/38→CUDA4,39→CUDA5; collector+packet→CUDA0. На коротких decode batches producer tap38 становитсяCUDA5, выполняется предусмотренный peer fallback в запланированную planeCUDA4. В native fallback также exact; locality для таких batch не заявляется. Единственное предупреждение в каждом local context сообщает первый такой случай, не является счётчиком всех переходов.

Producer streams записывают raw planes и сигналят их owned streams через существующий copy-event. Getter синхронизирует target/reorder, запускает чтение planes на их owned streams, packet stream ждёт events и завершает packing до возврата. Поэтому следующие target writes не перезаписывают ещё читаемые raw rows. Host snapshot/row swap/disable/destroy работают с каждым plane и дожидаются потоков. Распределение памяти и allocation failure сохраняют no_alloc и host fallback. Форматы GGUF/Engram и F32 arithmetic прежние. [Design](../../../DEEPSEEK_V41_1017_FEATURE_LOCAL_RETENTION_DESIGN.md).

## Границы проверки и следующий шаг

Текущий LOCAL default ON по запросу пользователя; исходный screen был opt-in (см. раздел promotion ниже). ASYNC+LOCAL вместе в этом этапе не измерялись. Не выполнены новый joint draft KV/logits/rollback gate, NLL/PPL,98K speed A/B, multimodal/parallel>1 и новая real-load проверкаctx176128. Native target106K correctness не заменяет эти gates. Не считать transfer microbench timings из предыдущего отчёта прогнозом общего PP.

Дальнейшее решение принимать по fresh default reference и профилю конкретных transfers, а не по выигрышу относительно более медленного central prototype. При отсутствии устойчивого выигрыша прекратить продвижение GPU bridge и перейти к следующему prefill bottleneck из плана.

## Реализация и численная семантика

Static const256 F32 table,1 KiB, заменяет повторные `ldexpf` для E4M3 bytes.
Операция умножения на прежний E8M0 scale сохраняется. При scale0xFF или E4M3
NaN code127/255 весь32-value block проходит прежний scalar decoder. Это
сохраняет NaN/sign/zero semantics и порядок для exceptional blocks.
Private opt-in `GGML_CPU_MXFP8_LUT=1` в архивной библиотеке; unset/0 возвращает
legacy branch. Проверка env один раз на row, не на значение. В остальных
форматах и CUDA decoder код не менялся; Q5_K/Q8_0 Engram не ускоряются этим LUT.
Нет новых buffers, threads, graph nodes или scheduler/lifetime hooks.
GGUF, precision, hash, WKV/gate, KV storage и rollback не менялись.

Короткий synthetic CPU GET_ROWS512 screen:MXFP8 median7.782 ->1.490 ms,
payload exact. Это не native PP. Дополнительный direct-row diagnostic с явно
загруженным original symbol: original7.458 ms, candidate OFF7.559 ms,
candidate ON1.479 ms. Эти CPU-only измерения выполнялись при model loading;
они показывают порядок и небольшой overhead OFF, не строгий end-to-end gain.

## Реальная цена CPU decoder: отдельный diagnostic profile

Однократно загруженная Q3, два contexts OFF/ON, wiki512/8K warm+1, без draft
и без generated continuation. LD_PRELOAD только в этом diagnostic, отдельном
от native speed. Контроль profile использует legacy branch candidate library.
Interposed decoder и CPU graph timers добавляют overhead; результаты ниже
не заменяют native throughput. После каждого prefix синхронизация; prefix
logits во всех8 trials точные. Hook проверен отдельно (`profile-check.log`).
Реальное число dequant calls строго48*T, не предположение о выборе backend.

| Prefix | Row calls | Decoder OFF ms | Decoder ON ms | CPU graph OFF ms | CPU graph ON ms | Wall OFF ms | Wall ON ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| wiki-test-512 | 24576 | 41.25 | 10.89 | 41.82 | 11.60 | 874.28 | 841.27 |
| wiki-test-8192 | 393216 | 665.86 | 170.43 | 675.03 | 182.19 | 9634.03 | 9653.82 |

На8K decoder time уменьшается665.9 ->170.4 ms при почти неизменном wall.
CPU time нельзя вычитать из wall как независимый последовательный участок.
В проверенной конфигурации decoder не ограничивает steady prefill throughput;
конкретный GPU critical path этим CPU profile не восстановлен. Объяснение
через уже существующее CPU/GPU overlap согласуется с данными, но отдельный
CUDA timeline нового overlap здесь не снимался.
Поэтому ещё одно уменьшение CPU decoder time через parallel GET_ROWS без
доказательства нового bottleneck пока не расширяем. Для8K требуется профиль
оставшейся GPU работы/ожиданий; запланированный Q8_0 KV остаётся следующим
самостоятельным этапом. Не объявлять его гарантированным ускорением PP.

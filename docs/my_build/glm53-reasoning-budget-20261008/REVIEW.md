В `/home/sergei/_llama_cpp/_models.ini` параметр записан как JSON-строка с внешними кавычками:

```ini
chat-template-kwargs = "{\"reasoning_effort\":\"low\"}"
```

Парсер получает строку вместо объекта и сохраняет значение под пустым ключом. `reasoning_effort` в шаблон не попадает. Встроенный шаблон этой GGUF выбирает `max`, когда нет распознанного значения `low` или `high`. В реальном prompt тестового запроса появился `Reasoning Effort: Max`.

Правильная запись в INI:

```ini
chat-template-kwargs = {"reasoning_effort":"low"}
```

Она проверена штатным парсером presets: kwargs содержат ключ `reasoning_effort` со значением `low`, бюджет остаётся 2048. Готовый раздел с глобальными defaults сохранён в `profile-corrected.ini`; исходный вариант находится в `profile-original.ini`.

Режим модели и бюджет являются разными настройками. Medium в Web UI отправляет `thinking_budget_tokens=2048`; он не устанавливает `reasoning_effort=low`. Max объясняет длинное размышление, но сам по себе не снимает бюджет.

На исходном установленном сервере, с исходным preset, глобальными `parallel=1`, `threads=20`, `flash-attn=1`, MTP и запросом `create html with svg "pelican on a bicycle"` получены следующие результаты:

| Seed | Токены размышления | Граница последнего reasoning delta | Первое content delta | Всего сгенерировано |
| --- | ---: | ---: | ---: | ---: |
| 1234 | 2048 | 2048 | 2050 | 4096 |
| 5678 | 2048 | 2048 | 2050 | 4096 |

Между последним токеном размышления и первым токеном ответа сервер выдал принудительный `</think>`. Следующий текст был HTML. Общий счётчик генерации включает размышление, закрывающий тег и ответ; после границы он продолжает увеличиваться. HTML в этих двух проверках ограничен общим `max_tokens=4096`; качество и полнота SVG не оценивались.

Превышение 2048 внутри reasoning при первой генерации не воспроизведено. Исправленную запись Low отдельно проверяли на той же модели с установленным сервером: в прямом запуске с корректным JSON размышление завершилось самостоятельно на 26 токенах, после него начался HTML. При этом тот запуск использовал автоматические 4 slots; сравнение с исходным preset не является проверкой скорости.

## Отдельное исправление Continue

Обнаружен другой воспроизводимый обход лимита: `generation_prompt` при Continue содержит уже написанный незакрытый reasoning. Если этот текст длиннее нового бюджета, обычный `accept()` считался подтверждением принудительно выданного конца размышления. Для GLM достаточно одного лишнего токена prefill, чтобы перейти в DONE без настоящего `</think>`.

В GLM-5.3 с MTP и бюджетом 8 после такого prefill сервер дополнительно сгенерировал 115 токенов reasoning (497 символов). Пользователь сообщил, что исходный сбой был при первой генерации; найденная ошибка Continue его не объясняет.

Подготовлено исправление в `common/reasoning-budget.cpp`, `common/reasoning-budget.h` и `common/sampling.cpp`: обработка prefill больше не продвигает принудительную последовательность. Настоящий конец размышления в существующем prompt по-прежнему распознаётся, включая тег из нескольких токенов на границе бюджета. Обработка вновь сгенерированных токенов сохранена.

Регрессионная проверка добавлена в существующий `tests/test-reasoning-budget.cpp`. Она покрывает открытый prefill сверх бюджета 0/2, естественный конец внутри prefill, клонирование и конец из нескольких токенов, пересекающий границу бюджета.

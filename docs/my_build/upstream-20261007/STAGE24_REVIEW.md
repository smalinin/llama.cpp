## Изменение

В общий `general-callback.h` добавлен opt-in суффикс режима `indexer`. Выбирается `MUL_MAT` с floating-весами F32/F16/BF16, двумерными операндами и шириной2..4. Вес должен иметь имя `blk.*.indexer.proj.weight`; у промежуточного узла проекции нет стабильного имени модели. Используется прежняя реализация scalar floating matmul: view одной колонки входа, `GGML_PREC_F32`, последовательное объединение результатов и запись в исходный выход. Новая схема округления внутри CUDA kernel не вводится.

Width1 и prefill сохраняют прежний путь. `raw-layout.h` побайтно сохранён из этапа23; политики raw/compressed attention, HC/router, routed FFN и compressor не изменены. Минимальные изменения выделены в `general-callback.patch`, `cache-replay.patch` и `projection-check.patch`.

Для проверки выбора операций добавлены счётчики замен по имени исходного веса. Во всех wide replay обработаны ровно восемь проекций: слои2/8/14/20/24/28/32/36. На длинной истории ширина2 заменяет1022 query-колонки каждой проекции, ширины3/4 —1023; завершающая одиночная колонка не пересчитывается. У width1 счётчики пусты. Анализатор проверяет точные значения для всех12 случаев.

## Полная модель

В одном последовательном GPU-процессе выполнены12 replay без захвата тензоров. Четыре прежних baseline/sparse/history контроля и восемь длинных историй cached/fresh widths1/2/3/4. Prompt6617 взят из ratio2 окна этапа22, фиксированные1024 ID — из explain-истории этапа19 на другом prompt. Это сравнение арифметики одинаковой последовательности. Draft, sampling и оценка качества свободного ответа здесь отсутствуют.

Cached путь сохраняет partial state, обрабатывает предшествующую историю, восстанавливает state, удаляет хвост через `seq_rm` и повторяет prefill последних4 prompt tokens, как исправленный harness этапа22. Fresh путь использует те же разбиения prefill без restore. Сохранены context8192, batch2048/ubatch512, F16 K/V, n_rs_seq3, один sequence, прежнее размещение на шести GPU и выключенные CUDA Graphs.

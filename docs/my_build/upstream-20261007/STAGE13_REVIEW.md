## Проверки на одинаковых входах

Из GGUF извлечены оригинальные `blk.0.hc_attn_fn.weight` F32 `[20480,24]` и `blk.0.ffn_gate_inp.weight` BF16 `[5120,384]`. HC-веса побайтно сверены с capture; оба исходных тензора повторно прочитаны и хешированы после экспериментов. Для HC post использованы все четыре настоящих операнда слоёв 0 и 2.

Для каждой из четырёх операций на Ada и Ampere выполнено по 11 вариантов: первые токены трёх capture-входов, каждый размножен до widths 1/2/4, плюс два полных настоящих широких batch. Все 88 вариантов дважды дали одинаковый результат; одинаковые колонки внутри batch также совпали побайтно.

| Операция на первом одинаковом входе | Ada: max width 2 / 4 против scalar | Ampere: max width 2 / 4 |
| --- | ---: | ---: |
| F32 HC mixes | 0 / 3,81470e-5 | 0 / 3,05176e-5 |
| BF16 router с явным FP32 | 9,53674e-7 / 9,53674e-7 | 9,53674e-7 / 9,53674e-7 |
| HC post слоя 0 | 0 / 0 | 0 / 0 |
| HC post слоя 2 | 0 / 0 | 0 / 0 |

Все 12 воспроизведений полных модельных матриц на Ada совпали с capture побайтно. На Ampere совпали 11 из 12; исключение - HC mixes width 4, max 7,62939e-5 против capture, снятого на Ada. Его повторные вычисления стабильны. Это сравнение разных архитектур, а не неудавшийся контроль воспроизведения на том же устройстве.

CPU double-проекция с однократным округлением результата в F32 даёт для HC scalar max ошибку 9,53674e-7, для Ada width 4 - 3,81470e-5. Для router это соответственно 4,76837e-7 и 9,53674e-7. CPU используется как численная опора; меньшая ошибка отдельной операции не гарантирует меньшую ошибку конечных logits.

Nsight на обеих архитектурах подтверждает смену пути: HC widths 1/2 используют `mul_mat_vec_f` с 1/2 колонками, width 4 - FP32 SGEMM и split-K reduction. Router scalar использует BF16/F32 `mul_mat_vec_f`; widths 2/4 преобразуют BF16 веса в F32 и выполняют FP32 SGEMM/split-K. Профилированные 44 варианта стабильны, все 56 файлов результатов, включая CPU references, совпали с обычными процессами. Наблюдения согласуются с разным порядком FP32-редукции; нового нарушения контракта явной FP32 precision не выявлено.

## Интервенции во всей модели

После штатной широкой операции callback пересчитывает выбранный floating MUL_MAT отдельным FP32 графом для каждого токена, объединяет колонки и подставляет выход перед следующей операцией. Используются текущие веса/входы модели через borrowed leaves; вложенный граф ограничен `3 * width` узлами. Исходные широкие операции также выполняются, поэтому runtime такого callback не является оценкой производственной стоимости.

Проверены три дополнения к контролю этапа 12:

- Только router: 2560 token-layer результатов на каждую широкую replay.
- HC и router: 5120 HC и 2560 router результатов, оба HC mixes каждого из 40 слоёв.
- Все обычные 2D floating MUL_MAT: дополнительно compressor projections и другие узлы, удовлетворяющие форме. Всего 8704/8800 результатов при widths 2/4; многомерные и quantized MUL_MAT этим правилом не охвачены.

Все девять replay завершились успешно. Все три scalar SHA совпали с native на всех 65 строках; при width 1 замены не выполняются. Вместе с capture завершено 12 модельных replay и шесть SHA-контролей против ранее сохранённых данных.

## Решение и следующий этап

Новый режим остаётся диагностическим. Проверка префикса впервые проходит обе ширины, но исходный ответ был длиннее 65 токенов; свободные продолжения, разные prompts, draft/rollback и acceptance не проверены. Преимущество по HTTP tokens/s не измерялось. Вводить пользовательский флаг или менять рабочий сервер на основании этого replay преждевременно.

После review следующий шаг - перенести сочетание FP32/scalar FA/scalar upgate/HC/router в изолированный экспериментальный путь для проверки свободной greedy off/on генерации с DSpark на нескольких prompts. Сначала подтвердить, что интеграция сохраняет scalar и текущий replay; затем сравнить полные token IDs до EOS/лимита. При совпадении ответов измерить acceptance и реальную стоимость; при новом расхождении локализовать его на той же истории. Большой остаток logits против scalar и расходы последовательных проекций остаются практическими ограничениями кандидата.

# Stage 32: DeepSeek-V4.1 restored KV

Base: my_build at 79e83668e8264b8eeb6dd88ead9ab9755a1b6167, with the uncommitted Stage31 changes. The Stage32 patch is relative to that recorded working tree. Source changes remain uncommitted for review. Installed binaries and presets are untouched.

DeepSeek-V4.1 raw SWA keys and masks are gathered in logical token-position order before attention, including the raw portion concatenated with compressed keys. Only rows visible to at least one query in the current stream participate. Padding depends on that logical set, not the highest physical row or old masked cells. Graph reuse checks the new extent. Stored KV, sequence metadata, compressed state, state formats, and the Stage27 tail rollback are preserved. The Stage31 gather helper is reused; GLM behavior is unchanged. Compressed quantized keys are converted through F32 before F16, because the CPU backend cannot directly cast Q8_0 to F16.

## Reproduction and validation

- `base-sources.json` and `base.patch` record the starting source state. `source-final.patch` is a zero-context Stage32-only patch; apply with `git apply --unidiff-zero` after Stage31.
- `build.py` copies Stage31's immutable candidate snapshot and rebuilds the model library using the original Release compile/link commands. All dependent private-header objects are recompiled; the manifest records commands, sources, reused object hashes and final library hashes. The server and GGML libraries are retained.
- `run-server.py` runs a separate localhost server, checks loaded library paths/hashes, and shuts it down in `finally`. It reuses the Stage3 prompt and Stage25 exact 6617-token input. File continuation must hit 1686 cached tokens plus one input token; the long RAM continuation must hit 6613 plus four. Before/first-after use disabled CUDA graphs; final uses normal CUDA graphs. Three native processes, five completions each. The first-after snapshot predates only the CPU quantized conversion fix; final validates the final binary. DSpark is off; no diagnostic callback is installed.
- `restore.cpp` uses the public sequence file save/load API, with prefixes 65/431/1031 and eight fixed continuation tokens. It writes every vocabulary logit for comparison, independently of greedy selection. The existing tiny fixture is checked with/without FA. `make-fixture.py` adapts the existing test-llama-archs fixture outside tests/, using seed1234, 64-wide attention heads, 32-wide indexer heads and compression ratio2. `run-fixture.py --label final` and `--gpu 1 --label final` cover F16 CPU with/without FA and Q8 CPU/CUDA with FA. Q8 V without FA is unsupported by the existing context API and is not claimed.
- `final-regression.json`: existing DeepSeek state API failure handling, save/load, recurrent rollback, batch allocation, Stage27 tail allocation, GLM sparse attention and Stage31 GLM file relocation controls. Seven final commands complete successfully. Internal cases are recorded in their logs.
- `analyze.py` verifies actual output bytes, finite values, true cache hits, reported comparisons, final source hashes and library hashes. Probability equality is only recorded when probability rows were actually returned. The long test requests n_probs0 and proves tokens/text equality, not full real-model logit equality.

## Scope

The preserved native session and query6796 reproductions are fixed. Full logits after file restore are bit-identical in the tested CPU/CUDA fixtures. Real session responses match tokens/text/top5 probabilities, and long fresh/cache responses match all1024 tokens/text. No universal equality across different batches, GPUs, sampling or speculative schedules is asserted. Historical Stage3's second-token text mismatch did not recur in the current before binary, but its probabilities differed; the long baseline still diverged at output180 exactly.

The logical reduction order changes fresh arithmetic, so a new build can produce different text from the old build. This is not a quality benchmark. Gather/casts have a cost, and long-context Q8 temporary memory can grow. The real model test uses F16/context8192; Q8 is tested on the small model. No installed server replacement, production DSpark arithmetic migration, acceleration claim or 128K benchmark is included.

Intermediate fixture setup failures are kept locally and excluded: the original 8-wide heads cannot hold Q8 blocks; a broad fixture-text substitution initially changed the MoE scoring ID; direct CPU Q8-to-F16 conversion was caught and fixed. Final fixtures, hashes and validation results are separate.

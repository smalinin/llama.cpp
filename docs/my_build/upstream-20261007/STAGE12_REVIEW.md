# Этап 12: scalar routed up/gate при сохранённом batched down

Этап 11 закоммичен по указанию пользователя: `dc7cdcef7`, `docs : record DeepSeek FFN activation rounding diagnosis`.

Проверено узкое согласование арифметики routed up/gate: эти две проекции и SwiGLU вычисляются отдельно для каждого токена штатным scalar CUDA-ядром, затем hidden объединяется для обычной batched down-проекции. На одинаковом входе hidden становится побайтно одинаковым, разница полного FFN уменьшается с 2,49594e-5 до 2,98023e-8. Это подтверждает причинность найденного в этапе 11 локального усиления.

**Во всём target-графе общая совместимость не восстановилась.** Scalar up/gate отдельно и в сочетании с FP32 floating projections/scalar attention всё ещё дают другой greedy-выбор на одной из ширин. Для сочетания всех трёх интервенций max/RMS различий logits даже выросли относительно предыдущего FP32/attention-контроля. Поэтому вариант остаётся диагностическим и не переносится в рабочий сервер.

Подготовлено для review перед следующим коммитом. Производственные исходники, установленные бинарники, модель и профили не менялись.

## Изолированный FFN

Использованы те же оригинальные веса всех 384 экспертов слоя 2, три сохранённых входа этапа 10 и неизменяемые библиотеки `stage8/candidate-bin`. HEAD `dc7cdcef7`, ветка `my_build_upstream_20261007`. Проверены те же Ada/Ampere UUID и все 32 SHA библиотек. Десять исходных тензоров весов общим размером 4 948 984 832 байта повторно хешированы после вычислений.

В каждом процессе сравниваются `native` и `scalar-upgate`. Router, expert IDs, routing weights, shared-эксперт, down-проекция и суммирование сохраняют прежнюю ширину batch. Для каждого токена выделяются только views входа и IDs, выполняются Q2_K up/gate и SwiGLU clamp, затем hidden собирается через concat. Новый CUDA-код не добавлен.

- Все 154 native-файла данных на Ada/Ampere побайтно совпали с этапом 11.
- Для scalar batch все сохранённые границы обоих режимов совпали побайтно, включая три разных исходных входа.
- На строго одинаковом входе для widths 1/2/4 routed hidden совпал побайтно на обеих архитектурах. Следовательно, исчезает и расхождение входных Q8_1 integer/scale полей down-проекции; CPU-проверка уравнений квантователя это также подтверждает. Новый GPU Q8 capture не требовался.
- Expert IDs всех колонок, включая реальные разные токены широкого capture, совпали между режимами. Одинаковые колонки и повторные вычисления стабильны.

Первый сохранённый вход, widths 2/4 против собственного scalar:

| Граница | Native max | Scalar up/gate max |
| --- | ---: | ---: |
| Routed hidden | 1,78814e-7 | 0 |
| Полный FFN | 2,49594e-5 | 2,98023e-8 |

При сравнении настоящих немного различающихся входов widths 1/2/4 max полного FFN после интервенции равен 5,96046e-8. Остаточные различия routing weights и down-арифметики сохраняются.

Завершены 66 изолированных вариантов FFN: по 22 на Ada/Ampere и ещё 22 с Nsight на Ada, каждый дважды. Профилирование сохранило все 154 выходных файла обычного Ada-процесса. В профиле есть 60 вызовов fused scalar Q2_K up/gate: 6 от native scalar и 54 от интервенции. Ещё 16 wide Q2_K вызовов относятся к native-контролю. Down остаётся на штатных scalar/batched Q3_K путях; up/gate fusion сохранён.

## Интервенция во всей модели

В отдельном target-only replay после prefill callback пересчитывает routed up/gate/SwiGLU каждого из 40 слоёв scalar-графом на текущих входах и IDs. Вложенный граф использует borrowed leaves, не более `6 * width` узлов и не обходит родительский модельный граф. Результат подставляется перед batched down. Исходные операции wide up/gate также были выполнены; поэтому runtime этого callback не используется как оценка производственной скорости.

Для каждой ширины 2/4 заменено ровно 2560 token-layer результатов: 64 токена по 40 слоям. Scalar-контроли ничего не подменяют. Prefill остаётся прежним.

Конфигурация сохранена: target DeepSeek-V4.1 Q2_K/Q8_0 Engram, шесть GPU в прежнем порядке, layer split `1,1,1,1,1,0.4`, F16 KV, контекст 8192, batch/ubatch 2048/512, один слот, 12 потоков, output capacity 4. Prompt 1655 токенов; та же фиксированная native-история этапа 9, 65 полных logits-векторов по 129280 значений. Draft и rollback отсутствуют.

Выполнены 12 replay, все завершились успешно. Восемь полных SHA-контролей подтверждают, что добавление границ callback/capture не изменило baseline и прежний FP32/scalar-FA результат, а все scalar-интервенции сохраняют native. Фактически загруженные библиотеки проверены через `/proc/self/maps` и SHA.

| Режим | Width 2: max / RMS logits против scalar | Width 4: max / RMS | Индексы разных argmax, width 2 / 4 |
| --- | --- | --- | --- |
| Baseline | 5,284104 / 0,244460 | 7,098978 / 0,279226 | нет / 19 |
| Только scalar up/gate | 4,535291 / 0,223503 | 3,656929 / 0,226403 | 19 / нет |
| FP32 float + scalar FA | 3,547752 / 0,212877 | 2,142161 / 0,193741 | 19 / нет |
| FP32 float + scalar FA + scalar up/gate | 6,022089 / 0,240509 | 4,098028 / 0,223626 | нет / 19 |

Индексы считаются с 0. Scalar во всех режимах выбирает native-токен `verify` (23393) на индексе 19. Для сочетания трёх интервенций gap `verify - check` равен +0,007679 при width 2 и -0,064684 при width 4 против native +0,294163. Малое изменение пути вычислений меняет сторону этой границы; улучшение одного промежуточного тензора не гарантирует уменьшения конечной ошибки.

Capture первого decode подтверждает, что **внутри настоящей модели** после сочетания трёх интервенций routed hidden слоя 2 стал побайтно одинаковым для widths 1/2/4. До замены max разница составляла 1,78814e-7. Тем не менее поздние logits и один greedy-выбор расходятся. Причинность локального FFN-эффекта доказана, но его устранение недостаточно для согласования всей цепочки.

## Решение

Scalar up/gate остаётся диагностическим контролем. Общая совместимость не прошла даже на фиксированной истории, поэтому свободная DSpark-генерация и новый HTTP benchmark для этого варианта не выполнялись. Совпадение 65 argmax только при width 2 не закрывает эти критерии. Установленный сервер не требует пересборки ради этого этапа.

Следующий шаг после review: снять первую оставшуюся разницу в цепочке HC/router/FFN после выравнивания attention и routed hidden, проверить её усиление на одинаковых входах. Только после кандидата, проходящего контроль обеих ширин, возвращаться к свободной greedy off/on генерации на нескольких prompt и оценке реального ускорения DSpark. Узкая унификация CUDA-редукции может уменьшить стоимость scalar up/gate, но сама по себе уже не обоснована как полное исправление.

Большие tensor/logit dumps, бинарники, полный модельный лог и Nsight traces находятся только в локальной папке `stage12/`. В Git подготовлены исходники диагностики, manifests, хеши, результаты и небольшие извлечения логов. Остановка для review перед следующим коммитом.

## Где меняется результат

На input749/query7366 основные границы всех40 слоёв точны. На input750/query7367 первая расходящаяся основная граница — `attn_out-24`; границы слоёв0–23 точны. Подробный захват показывает:

- Layer24 — самостоятельный top-k source. Он читает compressed KV и ключи indexer слоя20, но заново рассчитывает scores и top-k. Runtime ownership сохранён в `focused-output/model-sources.json`.
- Вход `attn_norm-24` проекции indexer одинаков побайтно. `idx_q`, видимые ключи и входная маска indexer также совпадают. Различаются20 из32 весов indexer.
- Веса извлечены из исходного GGUF: `blk.24.indexer.proj.weight`, BF16, shape5120×32. Проекция выполняется с `GGML_PREC_F32`. Scale равен1/64; это точная степень двойки, поэтому исходное отличие появляется до SCALE.
- Максимальное отличие исходной проекции — `1.1920928955078125e-7`, RMS `3.755472395083548e-8`. После масштаба max/RMS — `1.862645149230957e-9 / 5.867925617318044e-10`.
- Из7368 видимых scores меняются1711; max/RMS `9.5367431640625e-7 / 2.3374755707747005e-7`. Меняется ровно последний выбранный индекс, rank2047: scalar3607, wide1106.

Вывод основан на видимых операндах, основных границах и изолированном воспроизведении.

## Причинные проверки на замороженных входах

Все23 варианта выполнены на той же GPU, где работает слой24: logical CUDA3 из сохранённого UUID-порядка. Каждый вариант повторён, все повторы побитово точны. Использованы существующие harness этапов13/18 и один небольшой harness indexer.

| Проверка | Вариантов | Результат |
|---|---:|---|
| BF16 MUL_MAT проекции | 11 | Width1 и actual width4 точно воспроизвели модельные веса indexer после scale1/64. Один фиксированный вход на widths1/4 воспроизводит описанное округление. |
| Indexer + top-k | 8 | Scalar/wide scores и top-k воспроизведены точно на widths1/4. Замена только W wide→scalar возвращает все scalar scores и индексы; обратная замена возвращает wide. |
| Sparse FA | 4 | Scalar/wide выходы воспроизведены точно. Замена только mask wide→scalar возвращает scalar FA; обратная замена возвращает wide. |

При фиксированных scores сортировка возвращает одинаковый top-k для widths1/4. В этом случае расхождение инициирует округление проекции; правило обработки равных значений не устраняет различие исходных scores. CUDA kernel profiler в этом этапе не запускался; конкретная инструкция/редукция внутри MUL_MAT не устанавливалась.

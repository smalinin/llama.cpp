## Что именно проверялось

После первого фрагмента она не является свободным ответом на исходный prompt; совпадение её logits не оценивает качество такого ответа. Сравниваются разные способы декодирования одной истории. Input i имеет absolute position 23+i и предсказывает output i+1.

В первом модельном процессе выполнено 10 replay: прежние widths 1/3/4, прежний width 4 без trace, новые widths 1/2/3/4 и baseline95 widths 1/4. Trace не добавляет callback ask и границ graph. Десять frozen-input вариантов на каждой из Ada/Ampere, с повтором каждого, подтверждают причину:

- Скрытый нулевой хвост native-входа воспроизводит wide-выход на той же архитектуре.
- Удаление скрытого хвоста wide-входа возвращает точный native-выход.
- Замена только `n_kv_max` на wide-значение сохраняет native-выход в этих dense FA.
- Все четыре Ada replay исходных форм воспроизводят модельные captures побайтно. Ampere сравнивается с собственными локальными результатами.

Max FA-разницы для raw 512/768 равен 5,6982e-5 на обеих архитектурах. Для compressed ratio 2 это 1,71065e-4 на Ada и 5,69522e-4 на Ampere. Эти малые изменения затем усиливаются последующими операциями. Профилирование Nsight в данном этапе не повторялось.

## Диагностическая политика и SWA

Для каждого query с абсолютной позицией p сохраняются:

```
pad256(n) = max(256, ceil(n / 256) * 256)
raw = min(actual_raw_storage, pad256(p + 1))
compressed = ratio ? pad256(floor((p + 1) / ratio)) : 0
```

Ratio берётся из hparams загруженной модели; raw storage определяется по фактическому layout FA0. Raw и compressed сокращаются независимо, без перестановки видимых строк. Перед сокращением каждый удаляемый элемент исходной маски проверяется на `-inf`. Scalar attention при width 1 не заменяется. Остальные диагностические меры этапов 15-18 сохранены; один crop поверх production graph не проверялся как достаточное исправление.

Захват подтверждает raw storage 768 и raw extents 256/512/768. Ratio 1 compressed растёт на absolute 256/512/768/1024, ratio 2 - на 513/1025. Эти сдвинутые границы учтены, вместо общего условия «пересекли 512».

SWA содержит 128 видимых raw строк. На position 767 это physical indices 640..767. На position 768 - indices 0 и 641..767; на 770 - 0..2 и 643..767. Размер raw остаётся 768. Переход через конец кольца подтверждён сохранёнными масками всех четырёх ширин; visible count в каждом случае 128.

## Ограничения и следующий этап

Политика проверяется на свежей принятой истории одной последовательности, фиксированных padding-границах и SWA указанного размера. Произвольная компактизация, восстановление session, несколько slots и другие размеры raw storage не покрыты.

Проверенные K lengths ниже 4096. В CUDA sparse dispatch использует длину K, `n_kv_max` и архитектуру; равенство этих dense результатов не устанавливает политику для sparse. Согласование per-query размеров и параметров при переходе dense/sparse остаётся следующим шагом перед CUDA-переносом.

Callback включает повторные вычисления, CPU transfers, allocation и synchronization. Ускорение DSpark и production throughput не измерены. HTTP свободная генерация нового общего callback в этом этапе не запускалась; результаты 16/16 этапа 18 относятся к прежнему кандидату на своём наборе запросов.

Исходники, команды, SHA, полные logits и raw dumps сохранены в `stage19/`; в Git подготовлен компактный review-архив. Этап 19 не коммитить до review пользователя.

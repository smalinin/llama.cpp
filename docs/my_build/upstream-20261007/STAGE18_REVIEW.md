# Этап 18: padding raw/compressed KV в DeepSeek-V4.1

Дата: 2026-10-09. Ветка: `my_build_upstream_20261007`. Исходный HEAD: `6cc96b034`.

Этап 17 закоммичен по поручению пользователя. В этапе 18 найдены два дополнительных источника batch-зависимости: padding raw KV и compressed KV изменяет разбиение flash attention, даже когда добавленные строки полностью скрыты маской. Диагностическое восстановление размеров обоих участков даёт побайтное совпадение всех 256 logits explain и 95 logits baseline при widths 1/2/3/4.

Свободные DSpark ответы совпали с native во всех 16 сравнениях: N=1 8/8, N=3 8/8. Прежняя развилка explain244 устранена в обоих повторах N=3. Производственного CUDA-патча нет. Установленный сервер и профили не менялись.

| 231 | 254 | 3 | 231 | 0 | 256 / 512 |
| 232 | 255 | 2 | 232 | 0 | 256 / 512 |
| 232 | 255 | 3 | 231 | 1 | 256 / 512 |
| 232 | 255 | 4 | 232 | 0 | 256 / 512 |

Все четыре полных SHA logits этапа 17 сохранены. Первый расходящийся именованный выход на этих границах: `attn_out-0`. Предшествующие HC/attention norm совпадают. В FA слоя 0 совпадают побайтно Q, sinks, видимые K/V, индексы и значения маски, все op_params. Разница появляется только в batch, включающем абсолютную позицию256. Нерасходящиеся width2/4 для input231 также проверены.

Физические размеры подтверждены захватом, а не выведены из предполагаемого максимального top-k. У слоя 2 на этой границе K имеет 512 строк у scalar и 768 у wide, включая compressed-сегмент.

## Изолированный raw KV

Четырнадцать frozen-input вариантов проверены на Ada и Ampere, каждый с повторным побайтным контролем. Все восемь Ada-выходов исходных форм воспроизводят модельный capture точно.

- Добавление к scalar K/V нулевых строк с маской `-inf`, 256 -> 512, воспроизводит wide FA-выход побайтно.
- Удаление из wide только скрытого хвоста, 512 -> 256, воспроизводит scalar FA-выход побайтно.
- Это верно для обоих query и обеих архитектур; Q и все видимые данные остаются фиксированными.
- Max различия raw FA: 0,0002493858 на input231 и 0,0001442432 на input232; RMS около 2e-6. После downstream-операций малое отличие усиливается.

Nsight: используется одна специализация `flash_attn_ext_f16<512,512,1,8,...>`, но grid.x меняется 64 -> 128. Меняется разбиение Stream-K и последующее объединение `flash_attn_stream_k_fixup_uniform`. Все 28 profiler-выходов совпадают с соответствующими unprofiled-выходами.

## Первый кандидат и compressed KV

V1 убирает лишний raw padding для query до первой границы256. Все удаляемые строки проверяются на отрицательно бесконечную маску. Исправление оставлено в callback, исходный wide graph сначала выполняется как раньше.

Полный explain256 сохраняет все native argmax, в том числе `conditions` на индексе244, но logits ещё отличаются:

| Width | Max против scalar | RMS |
|---:|---:|---:|
| 1 | 0 | 0 |
| 2 / 4 | 1,62136459 | 0,02883344 |
| 3 | 1,68412971 | 0,03196139 |

Повторный захват сохраняет все четыре SHA v1. Именованные границы слоёв 0-19 теперь точны. На input232 первая оставшаяся разница в `attn_out-20`; на input231 в `attn_out-23`.

У модели слои 2-19 имеют compress ratio2, слои 20-39 - ratio1. Для ratio1 на той же границе256 расширяется compressed-сегмент. Дополнительный захват FA20 сохраняет оба проверяемых SHA v1 (width1/3); Q, sinks и все видимые K/V совпадают. После raw-crop длина K/V составляет 512 у scalar и 768 у wide: raw256 + compressed256/512.

Scale, bias, softcap и precision совпадают. `n_kv_max` различается: 384 у scalar и 640 у wide; точные uint32 op_params сохранены. В данных коротких dense FA вариантах это не причина наблюдаемой разницы: padding/crop воспроизводит оба выхода при сохранённых параметрах соответствующего исходного варианта.

Восемь дополнительных frozen-input вариантов на каждой архитектуре подтверждают вторую причину:

- Удаление скрытого compressed tail возвращает точный scalar FA20-выход.
- Добавление скрытого хвоста к scalar воспроизводит wide-выход на той же архитектуре.
- На Ada max составляет 2,66e-6 / 3,15e-6 для inputs231/232, на Ampere 2,06e-4 / 2,29e-4. Wide Ada/Ampere здесь не обязаны совпадать между собой.
- Nsight: FA grid.x 128 -> 192 на Ada, 128 -> 160 на Ampere. Все 16 дополнительных profiler SHA-контролей точны.

## Второй кандидат и полные logits

V2 восстанавливает raw256 + compressed256 для затронутых query перед первой границей256. У ratio2 compressed-сегмент уже имеет 256 строк и не сокращается. Новые guard-проверки исключают удаление видимых строк и неподдерживаемые размеры. Никакой точности новых матриц или нового CUDA kernel этот вариант не добавляет.

В одном процессе выполнены два SHA-контроля захвата v1, четыре explain256 replay v2 и четыре baseline95 replay v2. Все завершились успешно.

## Ограничения и следующий этап

- Вариант диагностический и намеренно ограничен первой границей absolute256. Более поздние raw/compressed padding-границы, переходы SWA ring и длинная генерация требуют отдельных контролей.
- Существующие scalar FA, projections, routed up/gate, HC/router, compressor и cached down остаются частью диагностического сочетания. Совпадение не получено одним лишь crop поверх исходного production graph.
- Callback повторяет вычисления и включает CPU transfers, allocation и synchronization. Его HTTP timings не являются оценкой ускорения производственного DSpark.
- Перед CUDA-переносом нужна общая политика вычисления attention при изменении padding, проверенная на следующих границах и контекстах. После этого - перенос согласованной арифметики без повторной callback-работы и замер production throughput.

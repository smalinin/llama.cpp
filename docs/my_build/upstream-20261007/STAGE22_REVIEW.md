## Изменение политики

В этапе 21 cached speculative запросы получили HTTP500: на absolute6617 source raw K имел256 строк при storage768, а callback требовал768. `get_n_kv()` использует округлённый physical `used_max_p1()`. `state_read_meta()` заново размещает восстановленные строки через `find_slot()`.

Новый `raw-layout.h` перед decode читает metadata однопоследовательного raw SWA cache и получает slots всего batch через const `find_slot()`. На копии позиций он воспроизводит overwrite/purge для каждого префикса batch и округляет последний занятый физический индекс до256, с ограничением storage. Живые cells, head и GPU-данные при планировании не меняются. В FA0 после реального применения batch проверяются последний extent и физический индекс каждого входного токена.

Общий header принимает `raw_query_extents`. Оба новых harness всегда задают этот вектор при генерации. Старое правило оставлено как fallback для прежних harness; политика compressed KV и остальные численные вмешательства сохранены. Перед удалением padding по-прежнему проверяется, что все удаляемые mask entries равны отрицательной бесконечности. Guard совместимости не ослаблен.

Серверный observer также использует физический план. Его dense/sparse счётчики теперь корректно учитывают все ширины, включая1; в этапе21 для покрытия учитывались только широкие batches. Это счётчики effective per-query predicate, без нового kernel profiler измерения.

## Изоляция и ограничения

Используются неизменённые32 snapshot-файла этапа8. В отдельной серверной папке заменена только `libllama-server-impl.so`. Общие `raw-layout.h` и `general-callback.h` используются в model/server harness. Серверный callback включён только при генерации, отключён у draft; precision восстанавливается и временные routed-down inputs очищаются после успешного decode. Prefill должен остаться без вмешательств. В model harness `n_rs_seq=3`; фактических speculative draft/rollback в нём нет. Один слот, F16 KV, context8192, batch2048/ubatch512, прежний порядок шести GPU, CUDA Graphs выключены. GPU-прогоны идут последовательно.

Первый запуск нового model harness завершился SIGSEGV до измеряемого replay: `ubatch_reserve()` оставляет элементы `seq_id` нулевыми, а новый helper разыменовывал их без назначения указателя. Исправлено присваиванием валидного указателя из входного batch. Неуспешный запуск сохранён отдельно и исключён из успешных проверок. Рабочий сервер не участвовал.

В следующем длинном запуске обычный width1 decode получил `failed to find a memory slot` на измеряемом выходе549. В harness отсутствовал обязательный `seq_rm()` после partial restore: raw/recurrent state восстановлен, но compressed KV хранит старый хвост до его явного удаления. Сервер выполняет это удаление перед повторным prefill. Пропущенный шаг добавлен; предыдущая матрица из16 replay и остановленный длинный запуск исключены из итоговой проверки серверного пути. Все19 случаев выполнены заново в одном запуске; только его результаты вошли в итоговые сравнения.

Покрывается однопоследовательный prefix-cache restore этого fork. Произвольная compaction, полные session-файлы, multi-slot, другие KV-типы и распределения sampling не сертифицированы. Диагностический callback повторяет вычисления; его timings не являются оценкой production speedup. Перед CUDA-переносом остаётся локализация численного расхождения длинного восстановленного контекста; затем перенос без повторной callback-работы и проверка correctness/throughput производственного кандидата.

Всего в итоговом запуске завершены19 модельных replay:12 cached128 и4 прежних SHA-контроля точны; длинные widths3/4 имеют описанное численное расхождение со scalar. Первый SIGSEGV и запуски с неполным partial restore сохранены отдельно и исключены. После завершения всех процессов на шести GPU осталось по15 MiB служебной памяти, utilization0%.

# DeepSeek-V4.1 exact histories and recorded verification replay

Stage25 left two long N3 failures at queries 7020 and 7401. This stage uses the unchanged Stage24 callback and raw-layout planner to separate fixed-width arithmetic from real verification/rollback scheduling. Production sources, installed server, profiles and all 32 Stage8 snapshot files are unchanged.

prepare-inputs.py extracts the exact 6617-token prompt and both native1024 histories from Stage25 JSON after checking original raw hashes. cache-replay.cpp retains the established model harness. Its cached case warms the fresh native history before partial restore, trims the restored tail and prefills the last four tokens. argmax_no_eog reflects the requests' ignore_eos=true setting without changing logits. Ten cases preserve two baseline95 controls and compare both histories at widths 1/2/3/4. All eight long cases retain all native IDs; all six wide/scalar full-logit comparisons are bit-identical. Fixed non-overlapping widths alone do not reproduce the failures.

prepare-server.py derives an isolated server from Stage25 and adds optional LLAMA_DSV41_CAPTURE logging after target decode. It records batch tokens, positions, all argmax values and full CPU logits only near queries 7020/7401. It does not add graph interventions. Two N3 requests reproduce the complete Stage25 answers, all 571/567 generation batches and their recorded physical-layout fields. Only experimental libllama-server-impl.so differs from the snapshot.

prepare-schedules.py builds actual and native-token schedules. verify-replay.cpp executes seq_rm followed by the recorded batch, checks the server's raw extents and first/last physical indices, and compares every correct-prefix output with scalar logits. Cached cases warm the full actual fresh N3 schedule before partial restore. Native variants replace every measured draft input with the corresponding native history token, preserving batch positions, widths and rollback calls. Every wide batch must select the same eight indexer sources; warmup counts are excluded.

All six verification cases finish successfully, including two baseline95 controls. The target-only actual replay matches all 904/1764 server argmax rows and all 22/55 saved full-logit vectors exactly. Both native-token variants still choose the same alternative at queries 7020/7401. Correct-prefix metadata matches between variants on 405/786 rows, and all 8/19 stored full-logit rows for those prefixes are exact. These counts include prefill where stated; repeated speculative queries are distinct rows.

The first scalar logit differences occur earlier: query6910/output294 for fresh, query7251/output635 for cached. In each case the first native-prefix physical-layout difference occurs at the same query: actual starts at raw cell0, scalar at cell766, both with raw extent768. The schedule reproduces the failure without executing the draft model or server acceptance code. Wrong future draft tokens are unnecessary in the measured replay. This localizes the reproduction to target computation under recorded rollback/layout; it does not yet identify the first affected internal operator or prove a specific KV allocator defect.

Reproduction order: prepare-inputs.py; build-replay.py; run-replay.py --cases cases.txt --output model-output --prefix replay; analyze-model.py; prepare-server.py; run-server-capture.py; prepare-schedules.py; prepare-schedule-replay.py; run-verification.py --cases verify-cases.txt --output verify-output --prefix verify; analyze-verification.py; record gpu-after.csv; verify-integrity.py; archive-review.py. GPU jobs run sequentially. Existing result directories must remain intact; repeated runs require new output paths. Each builder records source hashes, command and exit code; runners verify those hashes before loading the model. Parent sources and binaries remain under stages7/8/9/16/24/25.

The workspace preserves full logits, checkpoint data, capture vectors, binaries and logs. The review archive retains row metadata, tokens, responses, schedules, manifests, summaries, patches and compact callback/cache logs. raw-file-sha256.json records omitted artifacts. artifact-sha256.json verifies the review copies. Probability arrays are omitted with canonical hashes, as in prior stages.

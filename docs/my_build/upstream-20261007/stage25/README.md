# DeepSeek-V4.1 free DSpark generation with indexer projection control

Stage24 made the long fixed-history logits bit-identical across widths1/2/3/4. This stage integrates its unchanged general-callback.h and raw-layout.h into an isolated server and checks free greedy generation. Production sources, installed server, profiles and Stage8 snapshot libraries are unchanged.

The server derives from the Stage22 harness. The only functional change is enabling the indexer suffix in the diagnostic mode. Added per-decode indexer counters record replaced columns and the number of source projections; prefill and width1 must record zero. Original precision is restored after decode, routed-down temporary inputs are cleared, and the draft callback is disabled.

Five configurations run sequentially: snapshot-off, integration-off, candidate-off, candidate-n1 and candidate-n3. Each completes16 requests: the prior14 short/dense/sparse requests and two ratio2-long requests. Prior requests remain byte-equivalent JSON to Stage21. New long requests use the6617-token prompt, n_predict1024 and ignore_eos=true, with fresh and prefix-cache execution. They exercise free target token selection through positions beyond the previous query7367 boundary. This is a forced-length greedy correctness check; timings include diagnostic callback duplication.

Current native responses provide the reference for the two new requests. The prior14 native responses are also checked against immutable Stage21 results. Integration and candidate requests are compared with the corresponding current native request. Comparisons include complete token IDs, content and stop metadata. Four n_probs5/0 pairs and four fresh/cache pairs are recorded per configuration. Cached requests must reuse prompt minus four tokens and prefill only four tokens.

Reproduction: prepare-build.py, run-free-generation.py, analyze-free.py, record gpu-after.csv with nvidia-smi, then verify-integrity.py. GPU jobs must run sequentially. Existing output directories must be preserved and a separate destination used for repeated runs. The build reuses the recorded production object/archive inputs and changes only the experimental libllama-server-impl.so. Manifests record all32 binary hashes, source hashes, commands and loaded-library paths.

Raw responses, probabilities, server logs, binaries and memory monitoring remain in the workspace. The review archive omits full completion_probabilities, preserving their canonical SHA and all generated tokens/content. Callback events and cache logs remain available as compact text. The raw-file index records original file hashes.

Free-generation agreement does not measure production speed. After review, a passing candidate still requires a CUDA implementation without duplicate callback computation and whole-server correctness/throughput validation. Arbitrary cache states, multi-slot execution and full-session restore are outside this bounded matrix.

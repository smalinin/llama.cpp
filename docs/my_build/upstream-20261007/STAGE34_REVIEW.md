# Этап 34: CUDA MMF stride и сохранение draft-состояния

Этап выполнен в `my_build` поверх `45cbfc78d` по отдельному поручению пользователя. Review принят пользователем; исправления и результаты одобрены для коммита. Установленный сервер и рабочие профили не заменены.

## Исправления

**MMF.** Проверка выбора CUDA MMF разрешала FP16/BF16 stride 260 байт, поскольку проверяла кратность 4. Внутри ядра stride уже измерялся в half2/bfloat162, а загрузка требовала чётного числа этих элементов, то есть кратности 8 байтам. Теперь выбор MMF проверяет 8-байтное выравнивание. Несовместимая форма использует существующий MMVF или cuBLAS; assertion не отключён. Другие поддерживаемые MMF формы сохраняют прежний путь.

**Файл слота.** После стандартной target-части записывается версионированное дополнение: draft KV и внутреннее speculative state. Для MTP это включает отложенную hidden row и её позицию; для DSpark восстанавливается собственный draft-контекст. Используются существующие `llama_state_seq_*_ext` и `common_speculative_get/set_state`, которые уже обслуживают кеш в RAM.

Дополнение содержит magic/version, длины секций и проверку совместимости target/draft путей, описания draft-модели, типа speculation, n_max и версии sequence state. Повреждённый или несовместимый draft не подмешивается к target: restore возвращает ошибку и очищает затронутый слот. Перед загрузкой очищается прежнее target/draft/spec состояние, в том числе при чтении старого файла без дополнения. Запись выполняется во временный файл рядом с назначением; rename публикует результат только после сохранения обеих частей.

Проблема отсутствующего draft state также зарегистрирована в upstream: [issue #28619](https://github.com/ggml-org/llama.cpp/issues/28619). Здесь обе части хранятся в одном файле, что исключает случайное смешивание независимых target и draft файлов.

## Проверки CUDA

- Старая библиотека воспроизводит `GGML_ASSERT(stride_row % 2 == 0)` на исходной форме и на новой постоянной регрессии с корректно инициализированным backing buffer.
- **576/576** сравнений с CPU: по 288 на RTX 4090 D / Ada и RTX 3090 / Ampere. FP16/BF16, K=128/130, M=32/512/513, batch=1/4/8/9/16/32, четыре головы, contiguous/padded/permuted layouts. Среди них исходный stride 260 байт и соседние значения.
- **4/4** новых случая в существующем `test-backend-ops` проходят на RTX 3090. До исправления этот же тест падает на первом случае.

## Проверки сохранения слотов

До исправления Qwen MTP сохранял 678 target tokens, но после erase/restore получал `cache_n=0`, `prompt_n=679`. Контроль без erase использовал `cache_n=678` и только один новый токен.

Финальный сервер проверен с включёнными обычными CUDA graphs, без диагностических callbacks, при контексте 8192 на слот. Во всех строках ниже продолжение содержит 32 greedy токена; проверяются токены, текст, реальный `cache_n` и совпадение количества записанных/прочитанных байт. Для Qwen и GLM5NEXT файл переносился из слота 1 в слот 0. DeepSeek проверен на префиксе свыше 6 тысяч токенов; его draft действительно активен.

| Модель / режим | Сохранено токенов | cache_n после restore | Продолжение | После перезапуска |
| --- | ---: | ---: | --- | --- |
| Qwen3.8-Flash-Next, MTP, Q8 target KV | 678 | 678 | совпали | совпали, cache_n=678 |
| GLM5NEXT / GLM-5.3-Flash, MTP, F16 KV | 558 | 558 | совпали | совпали, cache_n=558 |
| GLM-5.3 IQ2_XXS Routed, MTP, Q8 target KV | 558 | 558 | совпали | не повторялся |
| DeepSeek-V4.1, DSpark N3, F16 KV | 6648 | 6648 | совпали | совпали, cache_n=6648 |
| TinyLlama, без draft | 71 | 71 | совпали | совпали, cache_n=71 |

После restore обрабатывается один новый токен вместо полного префикса. Для TinyLlama контекст ограничен training context модели, 128 токенами на слот.

Отдельно проверены **17** отказов восстановления на реальных моделях: обрыв заголовка/данных, неизвестные magic/version, завышенный размер, несовместимая подпись, лишние байты, повреждённые draft/spec секции. Каждый отказ оставляет слот пустым и пригодным для нового запроса. Старый target-only файл принимается и даёт ожидаемый полный prefill с MTP/DSpark. Native сервер прочитал target-часть нового speculative файла, включая корректный `n_read` всего файла. На DeepSeek повторный полный prefill из старого target-only файла дал другое продолжение (`legacy_tokens_equal=false`); это не успешное восстановление draft и не включено в критерий точности нового формата. Новый полный файл в той же серии сохраняет точные токены до и после перезапуска.

Новая проверка в существующем `test_speculative.py` прошла на локальной TinyLlama: draft-simple, сохранение, перезапуск, другой слот, совпадение ответа и reuse префикса. Там же проверена ошибка публикации файла: существующее назначение сохранено, временный файл удалён.

## Совместимость и границы

- Форматы публичных session/sequence state остаются 11/4. Native файлы не получают draft-дополнение. Старые target-only файлы не содержат draft; для восстановления без пересчёта их нужно сохранить заново новым сервером с включённым draft.
- Новый файл с draft требует той же пары моделей, путей и согласованных speculative параметров. Параметры target/draft KV проверяются существующей сериализацией; например, несовместимая транспозиция V корректно отклоняется.
- Это исправление сохранения текущего состояния. Checkpoint history для произвольного отката hybrid/SWA промпта, sampler RNG, произвольный sampling, multimodal и 128K на этом этапе не проверялись. Rewind за пределы доступного состояния по-прежнему может требовать prefill.
- Результат этапа 33 по скорости DSpark не меняется: для текущего DeepSeek/sidecar рекомендован native. Здесь исправлена потеря draft-кеша при file restore.

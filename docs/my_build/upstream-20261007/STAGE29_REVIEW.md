# Этап 29. Воспроизводимость кеша GLM5NEXT

Фикс этапа 28 закоммичен по поручению пользователя: `5a4de37b8` (`llama : fix GLM5NEXT unified KV concurrent decoding`). Проверки выполнены на соответствующей итоговой библиотеке этапа 28; совпадение исходников, библиотек и загруженных сервером путей проверено по SHA. Новый производственный код не добавлялся.

## Результат

Полная воспроизводимость RAM-кеша не подтверждена. У DFlash свежие генерации повторяются, но после возврата сохранённого prompt из RAM меняются вероятности и ответы. Повторное восстановление того же prompt также может изменить ответ. Простой повтор длинного prompt в заполненном слоте через context checkpoint в основном сценарии воспроизводим. Это два различных пути использования кеша.

Завершены 112 серверных ответов без падений; зарегистрировано 32 фактических cache hits. В таблице указано число совпавших пар по token IDs, тексту и полям остановки. Статус `passed` в исходных server manifests означает завершение HTTP-сценария, а не успешную проверку воспроизводимости.

## Локализация расхождения

- DFlash, RAM restore, pool-cache on: совпавшие пары fresh/fresh, fresh/reuse, reuse/reuse соответственно 3/3, 1/3, 1/3.
- MTP, RAM restore, pool-cache on: совпавшие пары fresh/fresh, fresh/reuse, reuse/reuse соответственно 3/3, 1/3, 1/3.
- DFlash, RAM restore, pool-cache off: совпавшие пары fresh/fresh, fresh/reuse, reuse/reuse соответственно 3/3, 1/3, 1/3.
- Native, RAM restore, pool-cache off: совпавшие пары fresh/fresh, fresh/reuse, reuse/reuse соответственно 3/3, 2/3, 2/3.

Между DFlash RAM pool-cache on/off совпадают 12/12 соответствующих ответов и 12/12 наборов возвращённых полей вероятностей.

Отключение pool-cache не устраняет расхождение DFlash после RAM restore: его нельзя объяснить только сохранением pooled keys или новым выбором full rebuild.

Численное расхождение сохраняется без speculative decoding и без pool-cache. Следующее место для диагностики - общий путь восстановления состояния: RAM state restore, последующее восстановление recurrent checkpoint и согласованность KV/indexer state. Это направление поиска, а не установленная внутренняя причина.

У DFlash с pool-cache on первая разница token IDs для ALPHA fresh/reuse появляется на индексе 2 (нумерация с 0), для GAMMA на индексе 5. Между двумя RAM reuse ALPHA отличается уже первым токеном. Непустые top-5 строки показывают численное отличие до разветвления генерации. Для BETA доступные вероятности меняются при одинаковых 64 выходных токенах.

Полноценных строк top-5: 885 из 7168 probability objects. Speculative-путь обычно возвращает полноценный top-5 только для первого токена, а дальше пустой список и logprob 0. Индексы и значения непустых строк сохранены в компактном архиве. Полные CUDA logits через HTTP не сохранялись; пустые строки не используются как численное доказательство.

## Сценарии и фактическое использование кеша

GLM-5.3-Flash-UD-Q4_K_XL, DFlash2-Q8_0, встроенный MTP или native без speculation. Unified KV, три слота, context 8192, batch 2048, ubatch 64, F16 KV. Шесть прежних GPU с закреплённым порядком UUID, layer split `1,1,1,1,1,0.4`, fit off. CUDA graphs включены штатно, RAM cache 2048 MiB, idle-slot caching включён. Запросы строго последовательные, temperature 0, seed 1234, максимум 64 выходных токена, `n_probs=5`, pre-sampling probabilities.

Основной сценарий: три коротких prompt этапа 28 в фиксированных слотах; порядок фаз fresh1, reuse1, reuse2, fresh2. Далее длинный prompt из 24 записей повторяется в слоте 0. Короткие межслотовые запросы фактически имели `cache_n=0`: это контроль повторной обработки, а не доказательство cache restore. Длинный prompt имеет 432 входных токена; для обоих reuse сервер восстановил checkpoint до 428 токенов и обработал оставшиеся 4. В логах подтверждён `restored context checkpoint` на позиции 427. Для каждого speculative-режима pool-cache on/off в основном сценарии совпали все 16 соответствующих ответов и доступные поля вероятностей.

Из-за отсутствия cache hits у коротких межслотовых запросов добавлен RAM-сценарий: три длинных различных prompt ALPHA/BETA/GAMMA, тот же последовательный порядок фаз, автоматический выбор слотов. Логи подтвердили восстановление подходящего prompt из RAM и context checkpoint; все шесть reuse-запросов каждого процесса имеют ненулевой `cache_n`. Несмотря на автоматический выбор, фактические slot IDs для ALPHA/BETA/GAMMA во всех четырёх фазах каждого RAM-контроля одинаковы: 2/1/0. После обнаруженного расхождения добавлены только два контроля: DFlash pool-cache off и native pool-cache off.

`cache_prompt` управляет повторным использованием prompt. `LLAMA_GLM5_POOL_CACHE` отдельно управляет оптимизацией pooled indexer keys; это разные кеши. GPU-процессы выполнялись последовательно.

## Полные logits при фиксированных decode-вызовах

Четыре CPU-прогона существующей маленькой GLM5NEXT из `test-llama-archs`: unified/separated KV, pool-cache on/off. Форсируются одинаковые token IDs, позиции и последовательность decode-вызовов; возможное численное отличие не меняет последующие входы. Сохраняются все 128 logits каждой строки.

- После префиксов 96/128/160 токенов сохраняются состояния всех трёх последовательностей. Для продолжения с переменным активным набором слотов все 20 строк совпали побитово после двух восстановлений в том же контексте и восстановления в новом контексте.
- Для отдельного трёхшагового продолжения все 9 строк совпали побитово после save/restore.
- После удаления трёх хвостовых токенов и повторного decode побитового совпадения нет: max abs `4.94765117764473e-9`, RMS около `1.08e-9`. Greedy token IDs не изменились. Отличие есть при обеих организациях KV и при выключенном pool-cache; конкретная операция не локализована.
- Между pool-cache on/off все 107 строк каждого прогона совпадают побитово, включая строки после rollback.

Маленькая CPU-модель не воспроизвела серверное RAM-расхождение большой CUDA-модели. Её успешный save/restore не закрывает этот критерий.

## Границы вывода

Падение unified KV исправлено коммитом этапа 28; эти проверки его не воспроизвели. Воспроизводимость RAM restore остаётся открытой, теперь с сохранённым последовательным воспроизводителем. Строгая побитовая воспроизводимость хвостового rollback также не подтверждена из-за малого CPU-отличия.

Одиночный длинный prompt и три RAM-prompt различаются. Сравнение RAM restore и повтора в заполненном слоте на одном и том же проблемном prompt не выполнялось; поэтому конкретный виновный компонент RAM/checkpoint/KV этим этапом не установлен.

Три несовпавших concurrent reuse ответа этапа 28 не объявляются объяснёнными: здесь найдено расхождение без конкурирующих HTTP-запросов, но старое фактическое расписание CUDA-батчей не воспроизводилось. Не проверялись sampling при ненулевой температуре, все возможные длины контекста, произвольные session files и GLM-DSA. Результат относится к GLM5NEXT / GLM-5.3-Flash. Ускорение не измерялось.

Установленный сервер и профили не заменены. Все GPU-процессы завершены. Производственный фикс по новому расхождению не добавлялся; результаты подготовлены к review перед новым коммитом.

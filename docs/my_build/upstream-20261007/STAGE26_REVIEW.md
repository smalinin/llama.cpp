## Разделение арифметики и speculative расписания

Prompt6617 и две native histories1024 извлечены из исходных JSON этапа25 после проверки SHA. Header `general-callback.h` и `raw-layout.h` побайтно совпадают с этапом24. Серверное prefill-разбиение сохранено. Cached фиксированный replay прогревает fresh native history, затем делает partial restore, удаление хвоста и повторный prefill последних четырёх токенов. Выбор argmax учитывает `ignore_eos=true`; сами logits не меняются.

Первая матрица содержит10 replay: два прежних baseline95 SHA-контроля и восемь длинных вариантов. Все шесть wide/scalar сравнений полных logits точны, max/RMS0/0. Все физические traces и счётчики восьми source indexer projections точны. Исходный baseline SHA `188c8690abade05294ac66643c56bc7727b21adb3ad6a65b5061e6ca0dfaed5b` сохранён.

Далее отдельный сервер выполняет только два длинных N3 запроса. После target decode он записывает токены входного batch и argmax каждой колонки; полные logits сохраняет около двух точек смены токена. Это CPU-захват готовых logits без новых вмешательств в граф. Пропуск14 предшествующих коротких запросов не изменил оба ответа, ни одну позицию/ширину generation batch и записанные поля physical layout по сравнению с этапом25.

Вторая матрица содержит шесть replay: два baseline95 контроля и actual/native расписания для fresh/cache. В actual используются записанные draft-токены; в native каждая колонка заменена правильным native-токеном. Позиции, ширины и вызовы `seq_rm` совпадают. Cached варианты предварительно исполняют полное actual fresh N3 расписание, затем восстанавливают partial checkpoint. Это сохраняет реальный прогрев и размещение кэша; подмена только measured будущих токенов не меняет прогрев.

Replay не запускает draft-модель и серверный acceptance. Actual повторяет все argmax и все сохранённые полные vectors сервера. Native варианты тоже расходятся с scalar на тех же первых queries6910/7251 и выбирают те же альтернативные токены на7020/7401. Для правильного actual префикса все405/786 row metadata совпали между actual/native; все8/19 сохранённых полных vectors этих префиксов побитово точны. Здесь учтён один prefill output; остальные строки — отдельные verification queries. Native-вариант может вычислять одну query несколько раз, поэтому его3/4 ошибочные строки argmax означают повтор одной границы, а не3/4 разных ошибочных токена.

## Первая физическая граница

Первая численная разница совпадает с первой разницей physical index для правильного префикса. На query6910/fresh и7251/cached широкий batch начинается с raw ячейки0; соответствующий scalar начинает с766. Raw extent в обоих случаях768. После этого расположение сдвинуто на две ячейки; на queries7020/7401 observed индексы110/150 вместо108/148 у scalar.

На первой границе fresh max/RMS разности logits равны0,98176169/0,19826196; cached —0,35004151/0,06750207. Токены там ещё совпадают. На actual точках смены токена max/RMS равны0,49248314/0,10030367 и0,48440790/0,09050875 соответственно.

Это воспроизводимое ограничение target-вычисления при recorded rollback/layout. Будущие ошибочные draft-токены не требуются для измеренного эффекта. Совпадение физической границы с численной разницей не доказывает, что виноват конкретный allocator, FA reduction order или recurrent state: первый внутренний tensor ещё не захвачен, frozen подмены не выполнены. Guards проверяют raw extents, source size и первые/последние physical indices каждого batch; trace сохраняет индексы всех колонок слоёв0/2/20.

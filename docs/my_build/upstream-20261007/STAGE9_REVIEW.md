42 HTTP-запроса и 49 replay-контролей завершились успешно. Коммита нет; остановка для review. Установленный сервер и рабочие профили не менялись.

## Replay и влияние диагностики

Во всех replay используется одна новая native-история. Prefill повторяет серверные вызовы 1139/512/4, `swa_full=false`; сохранены 65 полных векторов logits по 129280 значений. Single-token контроль воспроизводит все 65 native token IDs сервера.

При default-пути ширина 2 выбирает те же 65 токенов, ширина 4 отличается на индексе 19. Gap `verify - check` в этой позиции: +0,294163 при ширине 1, +0,006218 при ширине 2 и -0,011494 при ширине 4. Равенство argmax не означает равенство logits.

| Default decode | Максимальная абсолютная разница logits против width 1 | RMS разницы | Индексы разных argmax |
| --- | ---: | ---: | --- |
| Width 2 | 5,284104 | 0,244460 | нет в 65 строках |
| Width 4 | 7,098978 | 0,279226 | 19 |
| 16 scalar tokens, затем width 2 | 2,317842 | 0,165527 | нет |
| 16 scalar tokens, затем width 4 | 1,956277 | 0,148151 | нет |

Общий scalar-префикс уменьшает разницу: существенна накопленная история состояния, а не только текущая широкая операция. Это не проверка полного rollback-пути DSpark.

Экспорт входов всех 40 слоёв и итогового слоя 40 сохранил SHA256 **всех 65 logits-векторов** для widths 1/2/4. Узкий capture компрессора и attention слоя 2 также сохранил все три SHA256. В отличие от широкого capture этапа 8, эти наблюдения пригодны для диагностики обычного графа. Для width 2 первое заметное отклонение появляется около слоя 2; для width 4 отличия уже есть раньше.

Источники: [controls summary](stage9/controls-output/summary.json), [integrity](stage9/control-integrity.json).

## Локализованное отличие BF16-компрессора

На первом decode-вызове, слой 2, width 1 против width 2:

- Q первой позиции и её полная маска attention побайтно совпадают; доступны те же 956 строк из физического буфера длиной 1792.
- Из доступных K отличается только новая сжатая строка, физический индекс 1595. Максимальное отличие её элементов 0,0009765625; прежние видимые строки совпадают.
- На этом шаге не обнаружен доступ к дополнительным будущим строкам через маску. Это локальная проверка, не доказательство причинности всех decode/rollback сценариев.

Из GGUF извлечены `blk.2.attn_compressor_kv.weight` и `blk.2.attn_compressor_gate.weight`, BF16 [5120,512]. Проверены фактические входы/выходы CUDA и CPU double accumulation. Округление входа CPU до BF16 воспроизводит изменение точности широкого пути:

| Операция, width | Max error против CPU с FP32-входом | Max error против CPU с BF16-входом |
| --- | ---: | ---: |
| compressor KV, 1 | 2,98e-8 | 3,4113e-4 |
| compressor KV, 2 | 3,4130e-4 | 4,17e-7 |
| compressor gate, 1 | 5,96e-8 | 3,8320e-4 |
| compressor gate, 2 | 3,8344e-4 | 9,54e-7 |

Single-token MMVF использует FP32-вход, batched MMF округляет его до BF16. В отличие от router этапа 8, эти операции сейчас **не запрашивают `GGML_PREC_F32`**: это дополнительный источник численной зависимости графа от batch, а не новое доказанное нарушение явного precision-контракта CUDA.

Сохранены также CPU attention reference и реальные Q/K/V/mask/sinks. Double reference с отдельным контролем half-округления Q/scale не воспроизводит CUDA online softmax и half probability tiles. Его остаточную ошибку нельзя самостоятельно считать багом CUDA.

Источник: [attention-summary.json](stage9/attention-summary.json), [CPU reference](stage9/attention-reference.cpp), extraction manifests и tensor layouts в `stage9/`.

## Контроли точности

Выполнены отдельные процессы/контексты, внутри каждого режима widths сравниваются со своим width 1:

| Контроль | Различающиеся argmax, width 2 / 4 | Результат |
| --- | --- | --- |
| F32 KV вместо F16 | нет / 19 | Все logits побайтно совпали с F16 во всех пяти вариантах. Flash Attention здесь приводит K/V к F16 перед вычислением |
| FP32 для всех обычных float MUL_MAT, включая prefill | 23,28 / 19 | Полного совпадения нет; контроль меняет исходные logits prefill |
| То же, Flash Attention выключен | 30 / 30 | Полного совпадения нет |
| CUDA fusion выключен | 28 / 28 | Полного совпадения нет; сам scalar-контроль меняется относительно обычного режима |

Затем повышенная точность включалась **только после prefill** через диагностический callback, не запрашивающий tensor capture. Все три scalar-контроля сохранили native logits побайтно:

| Только decode | Max/RMS разницы width 2 против width 1 | Max/RMS разницы width 4 | Разные argmax width 2 / 4 |
| --- | --- | --- | --- |
| FP32 для BF16 MUL_MAT | 5,041233 / 0,229195 | 5,705829 / 0,233682 | нет / нет |
| FP32 для HC | 5,284104 / 0,244460 | 6,595134 / 0,256497 | нет / нет |
| FP32 для всех float MUL_MAT | 5,041233 / 0,229195 | 7,090881 / 0,304767 | нет / нет |

Совпадение выбора на этих 65 строках недостаточно: большие остаточные отличия logits остаются. Кроме того, HC-only контроль с общим scalar-префиксом 16 токенов снова отличается на индексе 19. Эти флаги не перенесены в производственный граф и не объявлены исправлением DSpark.

Источники: [no-fusion summary](stage9/no-fusion-output/summary.json), [decode controls](stage9/attention-capture-output/summary.json), [harness](stage9/capture-attention.cpp).

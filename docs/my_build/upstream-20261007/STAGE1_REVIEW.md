## Сборка и целевые проверки

- CUDA Release сборка сервера, benchmark и профильных существующих тестов прошла.
- CTest: 15/15, 28,12 с. После добавления целевой parser-регрессии parser был отдельно пересобран и весь его набор прошёл повторно.
- Backend ops на физических GPU 4 (sm_89) и 3 (sm_86): 1882/1882 на каждом, включая CPY и MUL_MAT_ID; отдельно 2/2 новых MoE-сценария на каждом.
- Исходная сохранённая библиотека падает с double free на TOOL_ID после закрытия безымянного tool call; исправленная проходит тот же сценарий и следующий tool call.
- EOG внутри draft: на существующей маленькой модели `stories15M-q4_0.gguf` исходная библиотека принимает 4 токена вместо одного EOG, исправленная возвращает только EOG и проходит. Начальная попытка с синтетической `llama-dense.gguf` не считается проверкой: эта модель имеет `no_vocab`, поэтому у неё нет EOG.
- Четыре архитектурных теста GLM5NEXT, GLM-DSA, Qwen4Exp и DeepSeek-V4.1 прошли на RTX 4090 D, RTX 3090 и CPU: численное сравнение и state roundtrip. Meta backend пропущен.
- Direct I/O: пять чтений с невыравненными смещениями и длинами по обе стороны границы 64 MiB, включая блок 192 MiB + 17 байт, совпали побайтно с эталоном в обеих версиях.

В standalone direct-I/O harness peak RSS составил 564044 KiB до исправления и 433148 KiB после: экономия примерно 128 MiB на этой нагрузке. Это измерение процесса harness, включая библиотеки; оно не является замером RSS реального сервера.

Неподдерживаемые backend-формы пропущены. Эти проверки не подтверждают все комбинации GPU split modes или квантования.

## Сравнение реальных моделей

Все 8 конфигураций прошли, все 32 стандартных ответа совпали с соответствующим запросом этапа 0 по тексту и token IDs. Счётчики draft/accepted и причины остановки также сохранились. Настройки запуска такие же, как в этапе 0; сравниваются прежняя и новая сборки внутри одного режима.

Диапазоны состоят из двух запросов; значимость небольших изменений скорости не установлена. В частности, первый GLM-DSA MTP greedy запрос оказался медленнее прежнего, второй вернулся в прежний диапазон. Prefill, sampling и индивидуальные GPU-пики сохранены в JSON.

Исходные greedy расхождения off/on GLM и DeepSeek сохраняются. Sampling GLM-DSA с MTP всё ещё различается между повторами, при этом первый и второй ответы каждый совпадают со своим аналогом в исходном baseline. DSpark по-прежнему не показывает выигрыша на этом prompt. Эти вопросы оставлены для заключительных этапов по указанию пользователя.

Дополнительные проверки прошли: 3 конфигурации, 14 запросов, все серверы завершились с кодом 0.

- Qwen4Exp, GGUF 103,69 GiB, `load-mode=dio`: четыре ответа совпали с обычной загрузкой. Во время загрузки в `/proc` зафиксированы четыре GGUF-дескриптора с флагом O_DIRECT. Peak RSS сервера 2,75 GiB; этот GPU-профиль не воспроизводит дополнительную RAM-копию большого CPU-тензора, экономия проверена отдельно standalone harness.
- GLM5NEXT, `ubatch=16`: все четыре запроса завершились без CUDA-ошибок; greedy decode 36,88–37,11 токена/с, prefill 193,33–197,55. Повторы внутри режима совпали. Ответы отличаются от `ubatch=512`; отдельный исходный baseline для ubatch 16 не снимался, поэтому различие нельзя приписать этим патчам. Проверка численной корректности MoE выполнена отдельно против CPU в backend-тесте.
- DeepSeek-V4.1 с DSpark, reuse после EOS: после четырёх обычных запросов выполнены два greedy запроса с `cache_prompt=true`. Оба использовали кеш из 1651 токена, завершились по EOS, вернули 120 token IDs и совпали с ответом без кеша.

Всего выполнено 46 запросов реальных моделей. Tool pointer и EOG внутри draft проверены целевыми сценариями; полноценный HTTP streaming tool-call сценарий отдельно не запускался. Проверки длинного контекста, нескольких слотов и других KV/GPU split вариантов остаются в следующих этапах плана.

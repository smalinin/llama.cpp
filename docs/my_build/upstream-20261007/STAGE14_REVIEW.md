# Этап 14: свободная greedy-генерация с диагностическим HC/router

Этап 13 закоммичен по указанию пользователя: `e235b05ba`, `docs : record DeepSeek HC and router batch diagnosis`.

**Кандидат не восстановил совместимость свободной генерации с native.** При DSpark N=1 и N=3 ответы расходятся на всех четырёх prompt. На baseline ранняя разница N=3 действительно сдвинулась с индекса 19 на 87; свежий контроль исходного сервера с теми же CUDA Graphs это подтверждает. Конкретная оставшаяся операция пока не локализована.

## Интеграция и её контроли

HEAD `e235b05ba4163773de7c87da7fb3574ee61f7afb`, ветка `my_build_upstream_20261007`. В локальную `stage14/experiment-bin` скопированы библиотеки этапа 8. Заменён только `libllama-server-impl.so`: временный `server-context.cpp` включает тот же код callback, что и replay. Использованы исходные flags и objects/static libraries `build-glm53`; исходная server-impl библиотека побайтно совпадает со snapshot, входы линковки хешированы. Общие библиотеки llama/ggml/CUDA остаются прежними.

Пересчёт включается только для target decode, когда единственный слот находится в состоянии `SLOT_STATE_GENERATING`. Prefill и warmup сохраняют штатный путь; callback draft-контекста явно отключён. После decode и синхронизации исходные precision узлов восстанавливаются: изменённый параметр не остаётся в повторно используемом графе для следующего prefill. В экспериментальном сервере output capacity фиксирована на 4, независимо от DSpark off/on.

Сочетание сохранено: FP32 floating MUL_MAT, scalar FlashAttention, scalar routed up/gate/SwiGLU при batched down, scalar HC mixes/router. Вложенные графы вычисляются после штатных широких операций. Они дублируют работу и включают дополнительные allocation, host transfers и синхронизации. Это диагностическая интеграция; её время не оценивает стоимость возможного производственного CUDA-патча.

Перед свободными запросами новый общий callback прошёл три replay widths 1/2/4: все полные 65-строчные SHA совпали с этапом 13. Затем выполнены контроли свободной генерации:

- Экспериментальный сервер без интервенции сохранил token IDs и текст во всех 8 запросах.
- Включённый кандидат с DSpark off также сохранил все 8 ответов, включая продолжения после 65-го токена.
- Все 21 пары запросов с `n_probs=5` и `n_probs=0` дали одинаковые token IDs и текст. Это проверка двух режимов возврата вероятностей, а не повторный benchmark с одинаковыми параметрами.

## Свободные ответы

Конфигурация сохраняет прежние шесть GPU и layer split `1,1,1,1,1,0.4`, F16 KV, контекст 8192, batch/ubatch 2048/512, 12 потоков, один слот, `fit=off`. Target DeepSeek-V4.1 Q2_K/Q8_0 Engram и исходный DSpark MXFP4; `p_min=0`, N=1 или N=3. CUDA Graphs отключены во всех текущих процессах. Фактически загруженные библиотеки проверены через `/proc/PID/maps` и SHA.

На каждом из четырёх prompt выполнены два запроса с temperature 0, seed 1234, без prompt-cache, с возвратом token IDs и лимитом 256 токенов. Baseline native заканчивается EOS на длине 95; остальные три native-ответа достигают лимита 256. Поэтому сравнение последних трёх ограничено этим префиксом свободной генерации. Все ответы кандидата с DSpark достигают лимита 256.

Индексы считаются с 0; acceptance приведён для запросов без `n_probs`. Совпадение полных token IDs с native не прошло ни в одном из 16 speculative запросов.

Свежий исходный N=3 на baseline, с тем же лимитом, вероятностями и отключёнными CUDA Graphs, расходится с native на индексе 19 в обоих запросах. Кандидат устраняет эту раннюю развилку, но затем выбирает `Wait` вместо `These` на индексе 87 и продолжает более длинный ответ. Это локальное улучшение согласованности, а не полное исправление.

Первые различия N=1 совпадают с этапом 9 для всех четырёх prompt. Полные 256-токенные ответы SVG/Python/explain побайтно совпали с прежним N=1; baseline отличается от прежнего N=1 начиная с индекса 94. Между новыми N=1/N=3 три остальных ответа также совпали полностью, а baseline отличается на индексе 235. Равенство двух широких режимов на фиксированной native-истории не означает равенства любых свободных продолжений и разбиений batch.

## Расширение replay до поздней развилки

Тот же callback проверен на всех 95 native-токенах baseline: 94 teacher-forced входа после prefill и 95 полных logits-векторов на каждую ширину. Draft и rollback отсутствуют; история, prompt и параметры совпадают с прежним replay. Все три SHA первых 65 строк сохранены. Scalar выбирает все 95 native-токенов, включая EOS.

| Width | Max / RMS logits против scalar | Различия argmax |
| --- | ---: | --- |
| 1 | 0 / 0 | нет |
| 2 | 5,533545 / 0,261774 | только 87 |
| 4 | 5,533545 / 0,261774 | только 87 |

Полные 95-строчные logits widths 2/4 имеют один SHA `de8b6e781411041a1ad09dd8f6930ec749fd9700d662b7b3dbacd3fa554bf64e`. На индексе 87 gap `These - Wait` равен +0,534012 у scalar и -0,242853 у широких decode. Выбираются IDs 10137 и 39059 соответственно. Совпадение позиции и выбранного токена с первым свободным расхождением подтверждает достаточность target batch-эффекта для этого случая; оно не устанавливает единственную причину всех остальных расхождений.

Всего выполнены шесть модельных replay и шесть SHA-контролей против ранее сохранённых данных. Источники: [extended harness](stage14/extended-replay.cpp), [manifest](stage14/extended-replay-manifest.json), [численные результаты](stage14/extended-summary.json), `extended-replay-output/*-rows.jsonl`.

## Решение

Кандидат остаётся диагностическим. Небольшой проверенный префикс был согласован, но более длинная свободная генерация выявила прежний остаточный target batch-эффект. Контроль перед производственным переносом не пройден. Результаты acceptance сохранены; производственный benchmark ускорения при одинаковых ответах не выполнялся. Время текущих запросов включает дублирование вычислений callback и различающийся объём ответов, поэтому оно не обосновывает оценку скорости будущего исправления.

Следующий шаг после review: снять границы target-графа вокруг query, предсказывающего токен 87, на этой же native-истории для widths 1/2/4; учитывать положение нужного токена внутри batch. Найти первую оставшуюся разницу после пересчёта HC/router, затем проверить операцию на одинаковых операндах и оценить узкое согласование её арифметики. Свободную генерацию и скорость проверять вновь после кандидата, проходящего весь ответ и несколько prompt.

[Integrity](stage14/integrity.json) фиксирует хеши библиотек, входов линковки и raw-данных. Большие logits, бинарники, полный временный серверный исходник и логи остаются в локальной `stage14/`. Curated responses сохраняют token IDs, текст, параметры, timings и stop; полные probability-массивы доступны в локальных raw responses, а их удаление из review-архива явно отмечено.

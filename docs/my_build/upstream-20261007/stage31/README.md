# Stage 31: ordered GLM5NEXT attention KV

Base: my_build at 79e83668e8264b8eeb6dd88ead9ab9755a1b6167. The Stage27 tail rollback, Stage28 concurrent pool cache and Stage30 server preclear changes are retained. Production source edits are uncommitted for user review. Installed binaries and presets are untouched.

The model graph gathers masked MLA keys and masks in token-position order. It sizes this view by occupied cells, padded to 256, independently of the highest physical cell. Indexed/compact path selection and graph reuse use the same occupied extent. Storage, writes, state format, pooled-key identities, and CUDA kernels remain unchanged. Other model architectures do not allocate the ordered inputs.

The archived source-final.patch has zero context; use `git apply --unidiff-zero` when applying it to the recorded base.

## Build

`build.py` copies the immutable Stage30 preclear binary snapshot into candidate-bin. It uses the existing Release compile/link commands, rebuilds every libllama object whose dependencies include either modified private header, and links a separate model library. Object names retain the models/ prefix to avoid a collision with src/llama.cpp. Unmodified external libraries are preserved. The manifest records source hashes, all commands, reused object hashes and final library hashes. Reused server/common objects do not depend on llama-graph.h. Run from the workspace, not an install directory.

The preliminary late-native run used candidate-late-bin and the initial model-library revision. The final candidate-bin includes the matching pool-cache graph-reuse check. Final-late-bin combines that exact final model library with the immutable Stage28 server implementation. This intentionally restores the old restore-before-idle-clear lifecycle in a test snapshot, proving the model change independently of Stage30's server fix. The final production source still includes Stage30. Per-run control manifests embed the exact build manifest; do not overwrite preserved snapshots while a server is running.

## Validation

- `fa-layout.cpp` with `ordered-helper.inc`, `make-fa-replay.py`, `run-fa.py`: the four Stage30 captured inputs plus synthetic shift, wrap, holes and shuffle. The fixture constructs the same gather/mask/F16 graph operations as the production helper. Physical-to-logical maps are an oracle from the complete captured row contents; no runtime data matching is added to the model. Run ordered and original FA on Ada and Ampere, F16 and Q8_0. Compare complete output bytes, independent repeats, and per-operation timings. Raw tensors and output arrays stay local.
- `ram-occupied-replay.cpp`, `ram-gpu-replay.cpp`, `run-cpu.py`, `run-gpu.py`: the existing tiny GLM5NEXT occupied-slot restore/rewind schedule. Compare complete logits, not just argmax.
- `restore-layout.cpp`, `run-restore-layout.py`: public file save/load API with an unchanged 431-token prefix. Dummy metadata occupies a foreign sequence before restore; both attention and indexer caches get matching dummy placement. It is removed before any computation. Actual first cells 0, 499, 4000, 33000 and 65000 test both layout and path-selection thresholds without computing irrelevant dummy tokens. Compare four full logit rows after restore against the fresh reference; run before/after, CPU/CUDA, F16/Q8_0. Dummy values are never visible to attention.
- `run-regression.py`: existing batch allocation, GLM5NEXT sparse attention, F16/Q8 state roundtrip/failure and recurrent rollback tests with the final library; CPU only to avoid overlapping the real-model GPU runs.
- `run-server.py`: original Stage29 RAM prompt schedule and two three-request parallel waves. Same GGUF, GPU UUID order, F16 KV, context8192, batch2048/ubatch64 and greedy settings as Stage30. Native uses pool-cache off; MTP and DFlash use pool-cache on. Servers run sequentially and exit through the existing lifecycle handler. Final native retains the Stage30 server; final MTP/DFlash use the late-clear server test snapshot.
- `analyze.py`: exact tokens/text/returned-probability comparisons, baseline checks, true RAM hit counts, compact responses, and final source hashes. Speculative empty probability rows are not full-logit observations. Parallel success is a liveness check, not proof of equality across different scheduling/batch histories.

The 256-cell logical padding still depends on the logical set of occupied cells. Different batches or different active sequences can use a different reduction shape; that is outside a physical relocation of the same KV data. The change does not promise universal bitwise equality across GPUs, backends or arbitrary sampling. Q8 fresh arithmetic on CPU or CUDA can change slightly when the ordered gather is converted to F16; the fixture records that separately. DeepSeek and unrelated indexer/recurrent numerical issues are not covered.

For measured performance use the operation timings directly. Stage30 versus Stage31 server timings are historical comparisons, not an interleaved benchmark. Full-model tests use context8192; the 65536-cell tests are tiny-model fixtures. No throughput or peak-memory claim for full-model fragmented 128K prefill is established.
